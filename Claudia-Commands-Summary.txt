1. SPRINT CREATION
------------------
Command: /claudia:sprint:create
Usage: /claudia:sprint:create "030" [--with-planning "path/to/planning.md"] [--title "Sprint Title"]
Parameters:
  - Sprint Number: 3-digit number (e.g., "030", "031", "032")
  - --with-planning [optional]: Path to planning document for requirement extraction
  - --title [optional]: Custom sprint title (default: "Sprint XXX")

Description: Creates a new sprint document with numbered identifier and
initializes sprint tracking. Requirements are now EMBEDDED directly in the
sprint document (no separate requirements files). Validates sprint number
format and checks for existing sprints to prevent duplicates.

Examples:
  /claudia:sprint:create "030"
  → Creates: .claude-shared/project-management/3-sprints/030.md with embedded requirements template

  /claudia:sprint:create "030" --with-planning ".claude-shared/planning/auth-planning.md" --title "Authentication Sprint"
  → Creates sprint with requirements extracted from planning document

Sprint Document Structure:
  - Sprint goals and objectives
  - Requirements (EMBEDDED - no separate files)
  - Sprint metrics tracking
  - Timeline information

⚠️ IMPORTANT: Requirements are NO LONGER in separate 4-requirements/ files.
All requirements live directly in the sprint document.


2. REQUIREMENTS MANAGEMENT (DEPRECATED)
---------------------------------------
⚠️ THIS COMMAND IS DEPRECATED - Requirements are now embedded in sprint documents.

OLD Command: /claudia:requirements:define
NEW Approach: Edit requirements directly in sprint document

Description: Requirements are NO LONGER created as separate files. Instead,
they are embedded directly in the sprint document created by /claudia:sprint:create.

To add/edit requirements:
  1. Open sprint document: .claude-shared/project-management/3-sprints/XXX.md
  2. Add requirements following the embedded template structure:

     ### Requirement N: [Title]
     **Priority:** High / Medium / Low
     **Complexity:** Low / Medium / High
     **Problem Statement:** [Description]
     **Success Criteria:** [List]
     **Technical Considerations:** [Notes]
     **Acceptance Criteria:** [Checklist]
     **Related Issues:** (Will be populated)

  3. Save the file - requirements are now part of the sprint document


3. SINGLE ISSUE CREATION (GitHub Integration)
----------------------------------------------
Command: /claudia:issues:create
Usage: /claudia:issues:create "sprint-number" --requirement N [--title "Title"] [--labels "label1,label2"]
Parameters:
  - Sprint Number: 3-digit sprint number (e.g., "030")
  - --requirement N: Requirement number within the sprint (e.g., 1, 2, 3)
  - --title [optional]: Custom issue title (overrides requirement title)
  - --labels [optional]: Comma-separated labels

Description: Creates a GitHub issue from a specific requirement embedded in
a sprint document. Automatically stores issue copy in 5-tickets/ folder,
updates sprint document with issue link, and tracks metrics.

Process Flow:
  1. Reads sprint document (.claude-shared/project-management/3-sprints/XXX.md)
  2. Extracts specific requirement by number
  3. Creates GitHub issue with requirement details
  4. Stores issue copy in .claude-shared/project-management/5-tickets/
  5. Updates sprint document with issue link
  6. Logs to audit trail

Examples:
  /claudia:issues:create "030" --requirement 1
  → Creates issue from Requirement 1 in Sprint 030

  /claudia:issues:create "030" --requirement 2 --title "Custom Issue Title" --labels "bug,priority-high"
  → Creates issue with custom title and labels

Output:
  - GitHub Issue: #N with full requirement details
  - Ticket Copy: .claude-shared/project-management/5-tickets/030-issue-N-title.md
  - Sprint Updated: Issue link added to requirement section

⚠️ IMPORTANT: No automatic PR creation. Manual implementation required.
Use /claudia:commit and /claudia:pr:create for implementation.


4. BULK ISSUE CREATION (GitHub Integration) ⭐ NEW
--------------------------------------------------
Command: /claudia:issues:multiple-create
Usage: /claudia:issues:multiple-create "sprint-number" [--labels "label1,label2"] [--skip "1,3"]
Parameters:
  - Sprint Number: 3-digit sprint number (e.g., "030")
  - --labels [optional]: Comma-separated labels applied to ALL issues
  - --skip [optional]: Comma-separated requirement numbers to skip (e.g., "1,3,5")

Description: Creates GitHub issues for ALL requirements in a sprint document
at once. Automatically discovers all requirements, creates issues, stores
ticket copies, and updates sprint document with all issue links.

Process Flow:
  1. Discovers all requirements in sprint document
  2. Filters out skipped requirements (if --skip provided)
  3. Creates GitHub issue for each requirement
  4. Stores ticket copy for each in 5-tickets/ folder
  5. Updates sprint document with all issue links
  6. Updates sprint metrics
  7. Comprehensive summary report

Examples:
  /claudia:issues:multiple-create "030"
  → Creates issues for ALL requirements in Sprint 030

  /claudia:issues:multiple-create "030" --labels "enhancement,UI"
  → Creates issues with labels "enhancement" and "UI"

  /claudia:issues:multiple-create "030" --skip "1,3"
  → Creates issues for all requirements EXCEPT 1 and 3

Output:
  - Multiple GitHub Issues: #N, #N+1, #N+2, etc.
  - Ticket Copies: .claude-shared/project-management/5-tickets/030-issue-*-*.md
  - Sprint Updated: All requirement sections updated with issue links
  - Summary Report: Shows created/failed counts

Advantages:
  - Batch processing of entire sprint
  - Consistent labeling across all issues
  - Time-efficient for sprints with many requirements
  - Comprehensive progress tracking

⚠️ IMPORTANT: No automatic PR creation for any issues.
Each issue requires manual implementation workflow.

6. TICKET MANAGEMENT
--------------------
Ticket Storage Location: .claude-shared/project-management/5-tickets/

Description: All GitHub issues created via Claudia are automatically stored
as local ticket copies in the 5-tickets/ folder for offline tracking and
complete traceability.

Ticket Filename Format:
  {sprint-number}-issue-{issue-number}-{safe-title}.md
  Example: 030-issue-42-implement-authentication.md

Ticket Content:
  - Ticket ID and metadata
  - Full GitHub issue content
  - Implementation tracking (commits, PRs)
  - Status updates
  - Implementation instructions
  - Traceability links

Automatic Updates:
  - Created when issue is generated
  - Updated via /claudia:commit
  - Updated via /claudia:pr:create
  - Tracks full implementation lifecycle

8. CREATE PULL REQUEST (WITH COMMIT HISTORY)
--------------------------------------------
Command: /claudia:pr:create
Usage: /claudia:pr:create "issue-id"
Parameters:
  - Issue ID: GitHub issue number (e.g., "21", "42")

Description: Creates Pull Request from existing issue and branch with ALL
commit history and proper linking. Does NOT create new branch - uses existing
branch created during commit workflow.

Features:
  - Verifies you're on correct branch for the issue
  - Checks that commits exist on the branch
  - Pushes branch to remote (if not already pushed)
  - Fetches issue details from GitHub
  - Gathers ALL commit messages from the branch
  - Creates comprehensive PR description with:
    * Issue overview and description
    * Complete list of commits with messages
    * Files changed count and git stats
    * Checklist for review
    * "Resolves #issue" footer
  - Checks for existing PR (won't duplicate)
  - Updates ticket file in 5-tickets/ with PR link
  - Logs to audit trail

Examples:
  /claudia:pr:create "21"
  → Creates PR from current branch
  → Includes all commits made for issue #21
  → PR description lists all commit messages

  /claudia:pr:create "42"
  → Warning if not on feature/issue-42-* branch
  → Asks for confirmation to continue

18. PROJECT COMMITMENT (WITH INTERACTIVE BRANCH CREATION)
---------------------------------------------------------
Command: /claudia:commit
Usage: /claudia:commit "issue-id" ["description"]
Parameters:
  - Issue ID: GitHub issue number (supports "21" or "030-issue-21" format)
  - Description [optional]: Custom commit description (uses issue title if not provided)

Description: Commits changes with full traceability to GitHub issues,
interactive branch creation, conventional commit standards, and automated
commit message generation.

Features:
  - Fetches issue details from GitHub automatically
  - Interactive branch creation with 4 options:
    1. Create from current branch
    2. Create from main
    3. Create from staging
    4. Stay on current branch (if already created)
  - Auto-generates branch name: feature/issue-{number}-{title}
  - Auto-detects commit type from issue labels (feat, fix, docs, test, chore)
  - Auto-detects scope from labels (frontend, backend, db, auth)
  - Stages all changes automatically if nothing staged
  - Updates ticket file in 5-tickets/ with commit info
  - Logs to audit trail

Examples:
  /claudia:commit "21" "implement authentication system"
  → Creates feature/issue-21-implement-authentication branch (if chosen)
  → Commits with message: feat(auth): implement authentication system

  /claudia:commit "030-issue-42" "add user validation"
  → Accepts both issue-id formats
  → Uses description as commit message

  /claudia:commit "21"
  → Uses issue title as commit message
