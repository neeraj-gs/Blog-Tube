================================================================================
                          CLAUDIA COMMANDS COMPREHENSIVE SUMMARY
================================================================================

This document provides a complete reference for all Claudia automation commands
and related shell scripts for sprint management, development workflow, and
project automation in the Blog-Tube repository.

================================================================================
                               CORE WORKFLOW COMMANDS
================================================================================

1. SPRINT CREATION
------------------
Command: /claudia:sprint:create
Usage: /claudia:sprint:create "030"
Parameters:
  - Sprint Number: 3-digit number (e.g., "030", "031", "032")

Description: Creates a new sprint document with numbered identifier and
initializes sprint tracking. Validates sprint number format and checks for
existing sprints to prevent duplicates.

Example:
  /claudia:sprint:create "030"
  → Creates: .claude-shared/project-management/3-sprints/030.md


2. REQUIREMENTS CREATION
------------------------
Command: /claudia:requirements:define
Usage: /claudia:requirements:define "Description" --sprint XXX [--planning planning-doc]
Parameters:
  - Description: String description of the requirement
  - --sprint XXX: Sprint number (required, e.g., "030")
  - --planning [optional]: Planning document reference

Description: Creates comprehensive, structured requirement documents with
sprint-based UUID tracking. Generates hierarchical UUIDs following format
XXX-YY (e.g., 030-01).

Examples:
  /claudia:requirements:define "Authentication System" --sprint 030
  → Generates: 030-01-auth-system

  /claudia:requirements:define "User Dashboard" --sprint 030 --planning auth-planning
  → Generates: 030-02-user-dashboard


3. ISSUE CREATION (GitHub Integration)
--------------------------------------
Command: /claudia:issues:create
Usage: /claudia:issues:create "requirements-file" [--title "Title"] [--labels "label1,label2"] [--milestone "Sprint 030"]
Parameters:
  - requirements-file: Path to requirements file
  - --title [optional]: Custom issue title
  - --labels [optional]: Comma-separated labels
  - --milestone [optional]: Milestone name

Description: Creates GitHub issues from requirements files with full context
and traceability. Auto-generates issue body from requirement content.

Examples:
  /claudia:issues:create "030-01-auth-system"
  /claudia:issues:create "030-01-auth-system" --title "Implement Authentication" --labels "feature,priority-high"


4. PULL/LIST ISSUES (GitHub Integration)
----------------------------------------
Command: /claudia:issues:pull
Usage: /claudia:issues:pull [--state open|closed|all] [--labels "label1,label2"] [--assignee "username"]
Parameters:
  - --state [optional]: Filter by state (default: open)
  - --labels [optional]: Filter by labels
  - --assignee [optional]: Filter by assignee

Description: Retrieves and displays all GitHub issues with filtering options,
status information, and integration with Claudia workflow tracking.

Examples:
  /claudia:issues:pull
  /claudia:issues:pull --state all --labels "feature"
  /claudia:issues:pull --assignee "neeraj-gs"


5. IMPLEMENT MANUAL COMMAND (Collaborative Development)
-------------------------------------------------------
Command: /claudia:implement:manual
Usage: /claudia:implement:manual "XXX-YY-ZZ-description"
Parameters:
  - Ticket UUID: Sprint-based hierarchical format (e.g., "030-01-01-database")

Description: Enhanced sprint-based human-AI collaborative TDD implementation
with multi-commit workflow support and complete traceability. Guides developer
through test-driven development process.

Examples:
  /claudia:implement:manual "030-01-01-database"
  /claudia:implement:manual "030-01-02-authentication"


6. CREATE PULL REQUEST
----------------------
Command: /claudia:pr:create
Usage: /claudia:pr:create "issue-id"
Parameters:
  - Issue ID: GitHub issue number (e.g., "21", "42")

Description: Creates Pull Request automatically from GitHub issue with branch
creation, proper linking, and auto-generated PR description with checklist.

Examples:
  /claudia:pr:create "21"
  /claudia:pr:create "42"
  → Creates branch: feature/issue-21-implement-theme-toggle


7. PULL ALL OPEN PRS
--------------------
Command: /claudia:pr:pull
Usage: /claudia:pr:pull
Parameters: None

Description: Lists all open Pull Requests with detailed status information,
review status indicators, merge status, and available actions.

Status Indicators:
  - Review: ✅ (approved), 🔄 (changes requested), 👀 (review required), ⏳ (pending)
  - Merge: 🟢 (mergeable), 🔴 (conflicts), 🟡 (unknown)
  - Draft: [DRAFT] indicator for work-in-progress

Example Output:
  PR #30 - "Implement Theme Toggle" 👀 🟢
  Branch: feature/issue-29-implement-theme-toggle → main
  Author: neeraj-gs | Created: 2025-09-22

9. AUTOMATED CODE ANALYSIS
---------------------------
Command: /claudia:review:analyze
Usage: /claudia:review:analyze "pr-number"
Parameters:
  - PR Number: Pull Request number

Description: Performs comprehensive automated analysis including:
  - Code quality assessment (scoring)
  - Security vulnerability scanning
  - Test coverage analysis
  - File type risk assessment
  - Overall risk scoring and grading

Analysis Components:
  - Security Score: /100 (credential detection, SQL injection, XSS, etc.)
  - Quality Score: /100 (code smells, complexity, best practices)
  - Test Coverage Score: /100 (test file ratio, coverage analysis)
  - Overall Grade: A-F with risk level (LOW/MEDIUM/HIGH/CRITICAL)

Examples:
  /claudia:review:analyze "30"
  /claudia:review:analyze "21"


10. INTERACTIVE CODE REVIEW
----------------------------
Command: /claudia:review:interactive
Usage: /claudia:review:interactive "pr-number"
Parameters:
  - PR Number: Pull Request number

Description: Guided, interactive code review process with step-by-step
evaluation across multiple dimensions:

Review Categories:
  - Description Clarity (clear/needs_improvement/insufficient)
  - File Scope Assessment (appropriate/broad/too_broad)
  - Code Quality Rating (excellent/good/fair/poor)
  - Security Evaluation (secure/minor_concerns/moderate_risks/high_risk)
  - Testing Coverage (excellent/good/fair/poor)

Final Actions:
  - APPROVE: Ready for merge
  - COMMENT: Feedback provided, no blocking issues
  - REQUEST CHANGES: Issues must be fixed before merge

Examples:
  /claudia:review:interactive "30"
  /claudia:review:interactive "21"

                           SECURITY ANALYSIS COMMANDS

11. COMPREHENSIVE SECURITY SCAN
-------------------------------
Command: /claudia:security:scan
Usage: /claudia:security:scan
Parameters: None

Description: Performs comprehensive security scanning across the entire project:

Scan Components:
  - Dependency Vulnerability Analysis (npm audit, pip, etc.)
  - Code Security Pattern Detection
  - Configuration Security Review
  - Overall Security Scoring and Grading

Security Patterns Detected:
  - Hardcoded credentials (passwords, API keys, tokens)
  - SQL injection vulnerabilities
  - XSS vulnerabilities
  - Command injection risks
  - Weak cryptography usage
  - Debug information leaks
  - Sensitive file exposure

Output:
  - Overall Security Score: /100
  - Security Grade: A-F (Excellent to Critical)
  - Component breakdowns with recommendations
  - Prioritized remediation guidance

Examples:
  /claudia:security:scan


12. TARGETED SECURITY AUDIT
---------------------------
Command: /claudia:security:audit
Usage: /claudia:security:audit "target"
Parameters:
  - Target: PR number, file path, directory, or glob pattern

Target Types:
  - PR Audit: /claudia:security:audit "21" (audits PR #21 changes)
  - File Audit: /claudia:security:audit "src/auth.js"
  - Directory Audit: /claudia:security:audit "src/components/"
  - Pattern Audit: /claudia:security:audit "*.env"

Description: Targeted security audit with detailed vulnerability assessment,
risk scoring, and specific recommendations for the selected scope.

Examples:
  /claudia:security:audit "30"                    # PR #30 audit
  /claudia:security:audit "src/auth/"            # Directory audit
  /claudia:security:audit "backend/src/models/"   # Models directory

13. COMPREHENSIVE TEST EXECUTION
--------------------------------
Command: /claudia:test:run
Usage: /claudia:test:run [test-args]
Parameters:
  - test-args [optional]: Additional arguments passed to test framework

Description: Automatic test framework detection and execution with detailed
reporting across multiple project types:

Supported Frameworks:
  - Node.js: Jest, Mocha, Vitest, Cypress
  - Python: pytest, unittest
  - Rust: cargo test, tarpaulin
  - Go: go test
  - Generic: common test patterns

Features:
  - Framework auto-detection
  - Test execution with timeout protection
  - Result parsing and metrics extraction
  - Quality scoring and recommendations
  - Detailed reporting and audit logging

Examples:
  /claudia:test:run
  /claudia:test:run "--coverage"
  /claudia:test:run "--verbose"


14. TEST COVERAGE ANALYSIS
--------------------------
Command: /claudia:test:coverage
Usage: /claudia:test:coverage [coverage-args]
Parameters:
  - coverage-args [optional]: Additional arguments for coverage tools

Description: Generates detailed test coverage analysis with metrics,
uncovered code identification, and improvement recommendations.

Coverage Tools Supported:
  - Node.js: Jest coverage, NYC, c8
  - Python: coverage.py, pytest-cov
  - Rust: tarpaulin, llvm-cov
  - Go: built-in coverage tools

Metrics Provided:
  - Overall Coverage Percentage
  - Line Coverage (covered/total)
  - Function Coverage
  - Branch Coverage
  - Coverage Grade: A+ to F
  - Quality Score: /100

Output Features:
  - Uncovered code identification
  - Coverage quality assessment
  - Improvement recommendations
  - Coverage targets by file type
  - Best practices guidance

Examples:
  /claudia:test:coverage
  /claudia:test:coverage "--html"
